# Adapt the thinking, not a fixed montage

These examples use synthetic, illustrative copy and contain no private media. Use them to choose an action for a new idea. Scene timings, number of elements, assets, palette and source geometry belong to the new project.

## Scattered messages become a board and a focused result

The [runnable graphics specification](examples/idea-to-results.json) is a twenty-second example. Check it without creating media with `node scripts/editor.mjs graphics instructions/examples/idea-to-results.json --check`. For a real render copy it into a new project, choose its own id, obtain the applicable copy review and follow [GRAPHICS.md](GRAPHICS.md).

| Passage | Meaning | Action and reason |
| --- | --- | --- |
| 0–3 s | Messages are scattered | Three illustrative items hold in separate positions. Each has a stable ID. |
| 3–6 s | Gather them in one board | The same items move continuously into their board positions. |
| 6–10 s | One place to review | The completed board holds so its grouping reads. |
| 10–13 s | Bring the important result forward | The selected item moves into focus while the others become quieter. |
| 13–16 s | Review that result | The resolved focus holds; no replacement object or image cut is needed. |
| 16–20 s | Try a small example | The final invitation appears over the settled state and holds. |

This optional `message-board` example preserves the approved copy and the same three object IDs throughout. It illustrates an explanation, not a claim that a product produced real results. Replace copy and durations with the current explanation. Other ideas can use the fifteen existing concepts unchanged; no family is required in every edit.

## A process with a visible cause and result

Phrase: a completed form triggers an acknowledgement, a reminder leads to confirmation, and the completed visit prompts feedback. Use one identifiable token/card through the route; draw the connection only after its input arrives; change the appointment state when the confirmation lands. End by returning to the opening unresolved state and showing its resolution. Use `automation-flow` for a four-step process or `route-stops` for the journey. Actual message screenshots are evidence; anonymous UI is labelled illustration. The scene should not invent a response rate or savings.

## A contrast that keeps its subject

Phrase: the same feedback record has a high or low score. Retain the record's identity while its position/score changes; use a shared scale and an explicit unit/source. A calm success state or restrained warning should follow the change, not precede it. `meter-receipt` can compare values; real before/after images use `evidence-wipe`. A product claim needs supplied evidence. Two randomly chosen photos do not prove improvement.

## A recorded explanation on a screen

Phrase: one layer connects an application to a tool. Focus on the named part of the actual capture, then draw or reveal the relationship and widen for the recap. Use `screen-focus` for a separate capture within presenter content, or `screen-recording` for a screen-only source. Preserve existing caption/pen layers and avoid placing a second highlight on an already marked feature. Choose layout from the source's legibility, not from a fixed presenter percentage.

## A map with successive highlights

The viewer should see each region's place in the whole country. Keep a verified map and use consistent colours, highlight one region and its label, then retain enough context before moving to the next. Resolve with the combined view. Verify names and geometry; decorative routes and synthetic random dots do not substitute for geographical accuracy. The supplied-map-image route is described in [GRAPHICS.md](GRAPHICS.md).
